# Контент-план в Telegram: технический прототип

Статус: прототип, ждёт одобрения Ульяны. Визуальная часть лежит в `index.html` (открывается в браузере, данные в localStorage).

## Что должно получиться
Бот в Telegram с кнопкой «Открыть план». Внутри Mini App с пятью вкладками:
- **Бренд**: сжатое позиционирование из Брендбука 2.0, только чтение.
- **Календарь**: месяц с точками на днях, под ним список выбранного дня, перенос даты в одно касание.
- **План**: темы по неделям, раскрываются в «когда / формат / сценарий». Можно добавить, править, заменить темой из идей, удалить, отметить снятым.
- **Идеи**: быстрые тезисы. Любое сообщение боту автоматически попадает сюда.
- **Снято**: архив отмеченного, можно вернуть в план.

## Схема

```
Telegram-чат с ботом ──сообщение──▶ Бот (webhook) ─┐
Mini App (index.html) ──fetch──────▶ API ───────────┼──▶ База (items, ideas)
```

| Часть | Что делает | Рекомендация |
|---|---|---|
| Mini App | Этот же `index.html`, слой `store` в нём заменяется на запросы к API. Тему, кнопку «назад» и вибрацию берём из `Telegram.WebApp`. | Без сборщика, один файл |
| Бот | Принимает текст, кладёт в «Идеи». Команды `/plan` (открыть приложение), `/idea текст`. Отвечает «записала». | grammY (Node) |
| API | `GET /api/plan`, `POST/PATCH/DELETE /api/items/:id`, то же для `/api/ideas`. | Cloudflare Worker |
| База | Две таблицы, см. ниже. | Cloudflare D1 (SQLite, бесплатно) |
| Хостинг | Mini App требует HTTPS-адрес. | Cloudflare Pages + Worker, один деплой |

Запасной вариант без своего сервера: Supabase (база и API готовые) + бот на Cloudflare Worker.

## Безопасность
- Токен бота выдаёт @BotFather, лежит только в секретах хостинга, в репозиторий не попадает.
- API проверяет подпись `initData` от Telegram (HMAC с токеном бота), иначе отказ.
- Доступ только для Telegram-id Ульяны (белый список). Чужим бот отвечает «это личный бот».

## Данные

```
items: id, title, kind (Рилс|Пост), date, format, series, script, done, created_at, updated_at
ideas: id, title, note, added
```
Поля совпадают с объектами в прототипе, переписывать интерфейс не придётся.

## Связь с репозиторием блога
`blog/06-content-plan.md` остаётся источником правды для стратегии. Приложение это рабочий инструмент для ежедневного ведения. Нужно решить, нужна ли выгрузка из приложения обратно в репозиторий (JSON-файл раз в день), чтобы Claude видел актуальный план и писал сценарии под него.

## Этапы
1. Утвердить прототип (поля, вкладки, что лишнее).
2. База и API, проверка подписи Telegram.
3. Бот: приём идей из чата, кнопка открытия приложения.
4. Подключить Mini App к API, поставить на телефон Ульяны, неделя обкатки.
5. По итогам недели правки.

## Что нужно от Ульяны для запуска

- Аккаунт Cloudflare (бесплатный) или согласие на другой хостинг.
- Ответить на вопросы из описания прототипа.
